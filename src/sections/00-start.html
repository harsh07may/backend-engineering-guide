The stack

ToolVersionRole
Node.js26 LTSRuns JavaScript on the server. It also runs .ts files directly by erasing the type annotations (type stripping).

Why raw SQL through `pg` and no ORM? An ORM (object-relational mapper) hides the queries, and the queries are what the database chapters teach.

Project setup

```bash mkdir orders-api && cd orders-api npm init -y && npm pkg set type=module npm i express pg redis zod npm i -D typescript @types/node @types/express @types/pg ```

Node's type stripping only removes types. Anything that needs generated JavaScript (enums, parameter properties, decorators) fails at startup. This `tsconfig.json` makes `tsc` reject that syntax up front:

```json title=tsconfig.json { "compilerOptions": { "noEmit": true, "target": "esnext", "module": "nodenext", "strict": true, "rewriteRelativeImportExtensions": true, "erasableSyntaxOnly": true, "verbatimModuleSyntax": true } } ```

Two rules follow from it: imports name the real file (`./app.ts`, not `./app`), and types are imported with `import type`.

```ts title=src/app.ts import express from 'express'; import type { ErrorRequestHandler } from 'express'; export const app = express(); app.use(express.json()); // parse JSON bodies into req.body app.get('/health', (_req, res) => { res.json({ ok: true }); }); // routes from later chapters mount here // Error handler: four arguments, registered last. // Express 5 sends thrown errors and rejected promises here on its own. const onError: ErrorRequestHandler = (err, _req, res, _next) => { console.error(err); res.status(500).json({ title: 'Internal Server Error', status: 500 }); }; app.use(onError); ``` ```ts title=src/server.ts import { app } from './app.ts'; const port = Number(process.env.PORT ?? 3000); app.listen(port, (error) => { if (error) throw error; // e.g. EADDRINUSE: the port is taken console.log(`listening on :${port}`); }); ``` ```bash node --watch --env-file=.env src/server.ts # run, restart on change npx tsc # type-check ```

`app.ts` builds the app and `server.ts` starts it. Keeping them apart lets tests import the app without opening a port.

Common mistake Copying Express 4 snippets. In Express 5 a bare `*` route must be named (`/*splat`), `req.query` cannot be reassigned, and `req.body` is `undefined` until a body parser runs.
